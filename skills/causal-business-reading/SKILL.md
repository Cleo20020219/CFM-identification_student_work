# 业务与数据读取

交付忠实于材料的目标与证据草稿。保留业务人员的问法，不要求用户先选定理或填写数学 JSON，不以送入 POINT 为目标。

- **已有系统请求、Schema、来源目录**：按当前合同生成完整候选；不要把本 Skill 再当一套输出格式。核对目标、字段归属、确定性状态和实际引用；细节以当前 Schema 为准。
- **直接审阅业务与数据**：读[业务核对要点](references/reading-checklist.md)，给出“要评价什么、如何比较、已有什么信息、关键缺项”的简洁草稿。没有实际运行接口时标为待审核。
- **接入或执行仓库流程**：读[运行接口](references/runtime.md)，用现有代码生成请求、保存原答和审核工作表。模型需要宿主提供工具才能执行这些步骤；仅附加本文件不会自动执行。

有数据文件时，先核对字段/数组名、形状、单位、编码和缺失说明，再读取授权范围内的内容。行数、完整名册或模拟生成信息不自动成为可用总体信息。

原文确实缺条件，向负责人追问；模型漏读或读错，定位原句后显式重读。保存原答和全部变化，不替模型修改 JSON，不按预期识别结果补条件。新增材料或条件须重新审核，首答与重读分开报告。

来源审核、科学批准与数学证明分开。审核后系统应用已有定理并重放证书；合法 JSON、Skill 完成和模型自评都不构成证明。信息不足、读取错误、覆盖缺口与已证明非点识别分别报告。

外部调用、材料分享和次数按当前用户授权；凭据仅由本地认证进程载入，不输出、不记录。禁止把参考答案或私有评分反馈发给被测模型。只报告真正执行的阶段；遇到合同冲突就定位报告，不绕过校验。
